🛜 LAN · No Internet Needed

LAN Chat Room

A Python terminal chat app for multiple laptops on the same Wi-Fi/hotspot. Zero dependencies, pure standard library.

Architecture
Concepts & Technologies Used
🔌
TCP Sockets socket
Module: import socket
TCP (Transmission Control Protocol) creates a reliable, ordered, bidirectional connection between two machines. We use socket.SOCK_STREAM which guarantees messages arrive in order with no data loss — perfect for chat. The server binds to port 55000 and listens for incoming connections. Each client connects to that port over the LAN.
🧵
Multithreading threading
Module: import threading
Threads allow code to run concurrently. The server spawns a new Thread for every client that connects — so 4 clients = 4 threads running simultaneously, each handling one connection. The client also uses a background thread to receive messages while the main thread waits for your keyboard input.
🔒
Thread Safety Lock
Class: threading.Lock()
When multiple threads share data (the list of connected clients), a Race Condition can corrupt it — two threads modifying the same variable at once. A Lock acts like a mutex: only one thread can hold it at a time. We use with lock: before touching the clients dictionary to prevent this.
📡
Broadcast Pattern Architecture
Design: hub-and-spoke model
All clients connect only to the server (hub), never directly to each other (spoke). When Alice sends a message, it goes to the server first. The server then loops through every connected client and forwards it to each one. This is called the broadcast pattern — one message in, N messages out.
Message Flow — step by step
1
Alice types "Hello everyone!"
Her terminal reads the line via input(), encodes it to bytes with .encode(), and sends it through her TCP socket using sock.sendall().
2
Server receives the bytes
Alice's dedicated server thread wakes up from client.recv(4096). It decodes the bytes back to a string and prepends her username and timestamp to form the final message.
3
Server broadcasts to all other clients
The broadcast() function acquires the Lock, iterates over the clients dictionary, and calls sendall() on each socket (except Alice's — she already sees her own message).
4
Bob & Priya see the message instantly
Their background receiver threads are blocked on sock.recv() waiting for data. The moment the server sends, they wake up, decode the bytes, and print to their terminal — all happening in parallel, in milliseconds.

The Core Loop — Server Side
# Server: accept a connection → spawn a thread for it → repeat forever
while True:
    client_sock, addr = server.accept()          # blocks until someone connects
    t = threading.Thread(
        target=handle_client,
        args=(client_sock, addr),
        daemon=True                             # thread dies when main program exits
    )
    t.start()                                   # run handle_client() in parallel

# Inside handle_client() — the broadcast:
def broadcast(message, exclude=None):
    with lock:                                   # acquire mutex → thread-safe
        for client in clients:
            if client is not exclude:
                client.sendall(message.encode()) # send to everyone else
